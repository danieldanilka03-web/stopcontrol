# СтопКонтроль — ИС мониторинга остановочных комплексов

Фронтенд (index.html + css/ + js/) и серверные функции Vercel (api/) с БД Postgres (Neon).

## Структура
- `index.html`, `css/styles.css`, `js/data.js` (справочники, демо-данные), `js/app.js` (приложение)
- `api/auth.js` — регистрация, вход, выход, текущий пользователь (bcrypt + JWT в httpOnly-cookie)
- `api/data.js` — REST API: остановки, заявки, осмотры, пользователи (с проверкой ролей)
- `api/_lib.js` — подключение к БД, автосоздание таблиц и начальных данных
- `schema.sql` — схема (для справки, создаётся автоматически)

## Запуск на Vercel
1. Загрузите папку в GitHub-репозиторий и импортируйте его в Vercel (Framework Preset: Other).
2. В проекте Vercel: Storage → Create → Neon (Postgres) → Connect Project. Переменная `DATABASE_URL` добавится сама.
3. Settings → Environment Variables: добавьте `JWT_SECRET` (любая длинная случайная строка).
4. Redeploy. Таблицы и демо-данные создаются при первом запуске.

Локально: `npm i && npx vercel dev` (нужен `.env` по образцу `.env.example`).

## Ограничения
Фото хранятся внутри JSON в БД (лимит тела запроса Vercel ~4,5 МБ) — для продакшена лучше Vercel Blob.

## Правила доступа (сервер, `api/_rules.js`)
- Остановки добавляет/удаляет только администратор; инспектор и диспетчер меняют лишь их статус.
- Инспектор создаёт осмотры и заявки только по остановкам своего района (район назначает администратор в разделе «Пользователи»).
- Заявки: статус, подрядчик и SLA меняют администратор и диспетчер; каждое изменение статуса пишется в историю.
- Автор заявки получает уведомление (колокольчик) при смене статуса. Просроченные по SLA заявки помечаются на канбане.
